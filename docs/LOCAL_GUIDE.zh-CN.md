# 轻报 · AI 辅助报销 MVP

参考 [Expensify App](https://github.com/Expensify/App) 的费用归集、对话录入和报销流转方式，独立实现的中文 Web MVP。它有自己的本地后端与数据库，不依赖 Expensify 的私有服务，也不代表其完整商业产品。

## 启动

需要 Node.js 24。当前 Mac 已安装依赖并编译本机 OCR。

```sh
npm install
npm run ocr:build
npm run build
npm start
```

打开 **http://127.0.0.1:3100**。开发模式使用 `npm run dev`，前端地址为 http://127.0.0.1:5173。

## 体验路径

1. 以「陈予安 · 员工」身份，点击「上传票据」。可以选择自己的文件，或点击弹窗里的 TEST 样例。
2. 核对商户、金额、日期、分类和用途，保存费用。
3. 在「我的费用」点击「生成报销单」，选择费用并提交审批。
4. 右上角切换「林知夏 · 审批人」。查看票据、异常提示和说明，审批通过或填写原因退回。
5. 员工可修改退回费用并再次提交；待审批费用可先撤回再修改。
6. 审批通过后，切换「许嘉宁 · 财务」登记模拟结算。全程保留流转记录，报销单支持 CSV 导出。

「轻报助手」支持输入“昨天打车 38 元，前往客户现场”，先生成待确认卡片，再由用户确认并保存。

## 已实现

- 图片 / PDF 上传、原件预览、本机 OCR、人工校对和手动录入。
- 费用列表、搜索与分类筛选、报销单归集、分状态金额统计。
- 单笔超标、缺少票据、相同文件或商户/日期/金额疑似重复、未来日期提示。
- 员工提交与撤回、审批退回与通过、财务模拟结算；服务端验证角色与状态。
- 对存在异常的报销单，审批通过前必须填写审核说明。
- SQLite 持久化、操作记录、CSV 导出、三种演示角色、移动端布局。
- 三张醒目标记 TEST 的合成票据，分别为交通 ¥38、住宿 ¥680、餐饮 ¥86。

## 当前 AI 能力与可选模型

**默认模式是 macOS Vision 本机 OCR + 明确规则 + 快捷文本录入。未配置大模型密钥。**

新增独立管理页面 **http://127.0.0.1:3100/agent**，也可以从员工端侧栏的「AI 配置与测试」进入。 界面会显示当前模式，不把规则结果包装成大模型结果。OCR 可能出错，票据字段保存前必须由人核对。

本机 OCR 通过 Apple Vision / PDFKit 实现，需要 macOS 和 Swift 工具链；PDF 最多读取前 10 页。其他系统可手动录入，需另外接入 OCR 才能自动识别。当前只支持 CNY，不做汇率换算，也不做税务发票真伪查验。

推荐从 AI 配置与测试页配置模型地址、名称和密钥，保存草稿后进行调试，通过后发布。也支持首次初始化时从 `.env` 读取默认设置：将 `.env.example` 复制成 `.env`，填写兼容 Chat Completions 的服务地址、密钥与模型名，然后启动服务。已经保存到数据库的模型地址与名称以工作台配置为准，后续调整 `.env` 不会覆盖它们。

```dotenv
AI_BASE_URL=https://your-provider.example/v1
AI_API_KEY=在本机填写你的密钥
AI_MODEL=你的模型名
```

启用后，服务端把 OCR 文本或用户对话发给所配置的模型，整理字段与草稿。票据原图不会由此接口发给模型。模型无法操作审批、保存或付款；连接失败会明确提示并回退。兼容模型须支持 JSON 输出；可以选择 JSON Object 或严格 JSON Schema，具体支持情况取决于服务商。目前未配置真实模型，外部模型效果与供应商兼容性尚未验证。

## AI 配置与测试

默认打开「示例展示」，包含费用录入、超标咨询、信息缺失三类固定预期回答，显式标记为非模型生成。示例不会读取提示词生成回答、发起外部调用、写入运行记录或创建费用。用户可自由选择是否接入，点击「真实 API 测试」后才使用自己的服务；未配置时禁止运行。示例可一键带入真实测试输入。

预置角色、业务指引、票据提取提示词统一维护于 `shared/ai-prompts.json`。新配置默认填入；已有配置不被覆盖，可以在对应分区点击「填入预置提示词」后自行编辑、保存。

- **提示词**：角色设定、业务指引、票据提取分别维护。票据提示词用于本机 OCR 后的模型整理。
- **模型连接**：填写兼容 Chat Completions 的 API 前缀与模型名，设置 Temperature、输出 Token 上限和超时。密钥按服务地址绑定，避免更换地址时误用旧密钥。
- **输出规范**：选择 JSON Object 或 JSON Schema、回答风格、字数上限和费用必填项。字段名固定以兼容费用表单；金额始终必填。服务端验证金额、日期、币种与结构，缺少已配置的必填项会转为追问。
- **能力边界**：可开关费用草稿、制度问答和票据字段整理。草稿关闭时服务端移除草稿；制度问答开关约束模型指令与本地回答，不是权限控制。业务审批权限仍由原有后端执行。
- **调试**：右侧输入场景，可查看响应、结构化结果、耗时、模型返回的 Token 用量和 Run ID。每次使用已保存的草稿配置，支持最近 8 条对话上下文。不生成模拟成功的模型回答；缺少密钥时不发起调用。
- **发布**：只有当前配置和凭据完成过一次成功的对话调试，才能发布。员工端对话与票据整理使用已发布快照。每次请求开始时固定使用该快照，发布不会中途改变它。
- **版本**：支持复制历史版本到草稿、切换已发布版本。回退不会覆盖编辑草稿。单次调试成功只验证连通性和输出格式，不代表已评估业务质量。
- **运行记录**：查看最近 30 条调试、员工端对话或票据模型调用。显示真实调用状态、配置摘要和输出；Token 未返回时显示不可用。

管理端和员工端在这个本机演示中共享单用户会话，并未实现正式管理员权限。API Key 保存在 `data/agent-secrets.json`，文件权限为 `0600`；它是本机权限保护的明文文件，不是生产级密钥托管。密钥不进入配置快照、页面返回或运行记录。模型对话和票据 OCR 文本的运行记录保存在本机数据库；本版本未提供自动清理策略。

自动测试使用受控模型响应桩检查请求参数、提示词生效、草稿/发布隔离、回退、校验失败和密钥不回显。这些是集成测试，不等于真实 LLM 实测。浏览器已验证无密钥状态、配置保存与刷新持久化。

## 数据与演示边界

数据在 `data/qingbao.sqlite`，票据在 `data/uploads/`；刷新页面或重启服务不会丢失。`data/`、`bin/`、`.env` 不进入 Git。初次启动会建立少量 TEST 演示数据。

右上角身份切换仅用于本机演示，不是真实账号认证。服务默认仅监听 `127.0.0.1`；不应直接公开部署。结算只更新演示状态，不连接银行、不发生付款。上线前还需要正式认证、权限隔离、部署和备份等工程工作。
